# Голосовой ассистент задач, напоминаний и встреч

**Версия:** 1.9.1  
**Тип:** локальное desktop-приложение для Windows 10/11  
**Язык интерфейса и запросов:** русский

Прототип для тестового задания «Горький код». Приложение принимает голосовые и текстовые команды, разбирает их локальной языковой моделью, проверяет сведения детерминированной бизнес-логикой и хранит записи в SQLite.

## Возможности

- Ввод текстом или запись голоса удержанием кнопки; распознавание через `faster-whisper`.
- Локальная LLM Qwen2.5-1.5B-Instruct классифицирует запрос и выделяет поля команды в JSON.
- Создание задач, напоминаний и встреч; просмотр записей за указанный период или активных (незавершённых) записей; поиск старых записей; перенос срока; изменение названия; удаление; отметка выполнения.
- Гибридный поиск: совпадение слов плюс семантическая близость на мультиязычных embeddings. Семантическая модель загружается лениво при первом поиске.
- Уточняющий диалог: **дата и точное время не подставляются автоматически**. Если чего-то не хватает, ассистент спрашивает и не сохраняет новую запись до получения ответа. «Утром», «в обед» и «вечером» не считаются точным временем.
- Уточнение периода просмотра, если пользователь просит показать записи, но не указал период; запросы «активные дела» выводят все незавершённые записи и не зависят от ошибочной классификации LLM.
- Изменение записи по названию или ID: переименование, изменение даты/времени; если поле не уточнено, ассистент задаёт вопрос. Неоднозначный выбор записи требует уточнения.
- Текстовый ответ остаётся доступным всегда; Windows TTS озвучивает ответ.
- SQLite сохраняет записи между запусками. Код не передаёт запросы внешнему LLM API.
- Действия с базой выполняются отдельными короткоживущими SQLite-соединениями; виджеты Tkinter обновляются только в главном потоке.

## Требования

- Windows 10/11, Python 3.13 (проверка синтаксиса и тестов выполнена в Python 3.13; реальный инференс моделей следует проверить на целевом ПК).
- Интернет нужен при первом запуске для загрузки языковой модели, Whisper и embedding-модели. После загрузки инференс локальный; семантический поиск переключается на поиск по словам, если embedding-модель недоступна.
- Микрофон нужен только для голосового ввода; текстовый режим не зависит от микрофона.
- Несколько гигабайт свободного дискового пространства для моделей и кэша.

## Работающий прототип и установка

**[Скачать работающий прототип можно в разделе Releases](https://github.com/PRANGATE/test_zadanie_assistent_llm/releases/tag/v0.1.1)**

В архиве находится установочный `.bat`-файл, который автоматически подготовит окружение.

**Инструкция по запуску:**
1. Скачайте релиз и распакуйте папку с проектом.
2. Запустите `start_assistant.bat` (скрипт создаст виртуальное окружение и установит все зависимости).
3. Запустите приложение (через ярлык или основной скрипт).
*Примечание: при первом запуске потребуется время на скачивание весов моделей Whisper и Qwen, поэтому требуется подключение к интернету.*


## Автоматические проверки

```powershell
python -m unittest discover -s tests -v
python -m compileall -q assistant main.py tests
```

Тесты запускаются без скачивания больших моделей: используются тестовые LLM/encoder и временная SQLite-база. Они проверяют даты и относительные интервалы, создание и уточнения без значений по умолчанию, поиск, операции с записями, работу с потоками и выбор нового аргумента Transformers `dtype`.

## Исторические изменения в 1.7.0

- Исправлен вывод активных дел: запросы «вывод/выведи активные дела», «покажи активные задачи» идут в режим списка и фильтруют выполненные записи. Для запросов по дате применяется фильтр периода.
- Добавлено изменение названия записи; новое название задаётся в кавычках или словами после названия существующей записи.
- Запросы «измени время/дату» и «перенеси» маршрутизируются в изменение срока даже при ошибочной классификации LLM.
- Для неполной команды «измени запись» появляется уточнение: название или срок. Для неоднозначной цели ассистент просит уточнить запись и не изменяет случайную.
- Добавлены девять регрессионных тестов для активного списка, переименования, редактирования и переноса.


## Уточнения без зацикливания (1.9.1)

- На каждый вопрос об отсутствующей дате/времени выдаются короткие примеры допустимых ответов и команды управления диалогом.
- Время понимается в форматах `15:30`, `22:00`, `22 00`, `в 22`, `10 часов вечера`, `15 часов 30 минут`. Слова «вечером/утром/в обед» сами по себе не принимаются за точное время.
- Если дважды не удаётся разобрать ответ, сообщение подсказывает ввести значение текстом или попросить вариант. После трёх неверных попыток незавершённое действие отменяется без сохранения или изменения записи.
- Новая команда (`покажи активные дела`, `найди…`, `создай…`, `перенеси…`) может прервать ожидающий вопрос и начать новую операцию.
- Для значения, которого не хватает, можно написать `предложи время` или `предложи дату`. Локальная LLM предлагает один проверяемый вариант; база не изменяется, пока пользователь явно не подтвердит его фразой `да`, `да, хорошо`, `подходит` или `конечно`. Предложение не является значением по умолчанию. Если модель не вернула корректный формат, используется явно обозначенный запасной вариант с той же обязательной процедурой подтверждения. `Нет` позволяет отказаться от предложенного варианта, а `не надо`/`отмена` полностью отменяет незавершённую операцию.
- Ответы на уточнения обрабатываются отдельно от классификации исходного запроса: валидное время/дата изменяет состояние диалога, а не запускает новый разбор команды.

## Архитектура

```text
Tkinter UI
  ├─ текстовый запрос ──────────────────────┐
  └─ микрофон → faster-whisper (STT) ───────┤
                                            ↓
                               LocalLLM (JSON intent)
                                            ↓
                           AssistantEngine (валидация,
                            даты, уточняющий диалог)
                                  ┌─────────┴─────────┐
                                  ↓                   ↓
                         Repository / SQLite   SemanticSearch
                                              (Transformers +
                                               mean pooling)
                                  └─────────┬─────────┘
                                            ↓
                             текстовый ответ → Windows TTS
```

LLM не выполняет SQL и не изменяет базу напрямую. Приложение перепроверяет даты/время по исходному запросу и не принимает придуманные моделью дату или ID как надёжный факт. Удаление и изменение не выполняются по неоднозначной ссылке на запись.

## Требования тестового задания: статус

| Требование | Статус в этой сборке |
|---|---|
| Создание задач и напоминаний | Реализовано; дата и точное время обязательны, иначе идёт уточнение |
| Создание встреч | Реализовано с уточнением недостающих даты/времени |
| Просмотр по периоду | Реализовано для распознанных периодов и дат; без периода задаётся вопрос |
| Поиск старых записей естественным языком | Лексический + локальный семантический поиск; качество нужно оценить на пользовательских примерах |
| Хранение между запусками | SQLite |
| Голосовой ввод / текстовый ответ | Реализовано; STT использует `small` на CPU по умолчанию |
| Голосовой ответ | Windows TTS включён, если доступен; текстовый ответ сохраняется при ошибке TTS |
| Уточняющий диалог | Реализован для типа, даты и точного времени; поддерживаются ответы на уточнение и отмена |
| Перенос, изменение названия, удаление, отметка выполнения | Реализовано; покрыто тестами |
| Ссылка на работающий публичный прототип | [перейти к релизу](https://github.com/PRANGATE/test_zadanie_assistent_llm/releases/tag/v0.1.1) |

Дополнительные пункты, которые остаются за пределами текущего прототипа: реальные уведомления в заданное время (записи хранятся, но планировщик уведомлений не реализован), обнаружение конфликтов встреч, повторяющиеся события, календарная интеграция и многопользовательский режим. Публичный прототип потребует отдельной web-обёртки/веб-версии и развёртывания; локальное desktop-приложение нельзя честно представить публичным URL.

## Совместимость и предупреждение `torch_dtype`

`assistant/compat.py` выбирает `dtype` для Transformers `>=4.56.0` и оставляет `torch_dtype` только для старых версий, где ещё требуется старый API. В поддерживаемом диапазоне зависимостей ожидается актуальный Transformers, поэтому предупреждение о deprecated `torch_dtype` не должно возникать.

Ссылки на документацию, проверенные 25 октября 2026 года:

- PyTorch для Windows и Python: https://pytorch.org/get-started/locally/
- Transformers API модели и `dtype`: https://huggingface.co/docs/transformers/v4.56.1/en/main_classes/model
- Transformers на PyPI: https://pypi.org/project/transformers/
- faster-whisper: https://pypi.org/project/faster-whisper/

## Известные ограничения

- Автоматические тесты не подменяют проверку инференса Qwen/Whisper, настоящего микрофона, Windows SAPI/TTS и GPU на целевом компьютере.
- Whisper использует CPU/int8 как наиболее предсказуемую конфигурацию Windows. GPU-ускорение Whisper не включено автоматически.
- Семантический поиск использует encoder из Transformers и простое mean pooling с attention mask. Он не гарантирует правильное ранжирование каждого запроса; если модель не скачалась, приложение использует поиск по словам.
- Поддержка естественных дат ограничена формулировками, перечисленными в тестах; неразрешённая неоднозначность должна уточняться.

## Безопасность и данные

Все задачи хранятся в локальной SQLite-базе. Репозиторий не отправляет содержимое базы в облачный API. Загрузка моделей из Hugging Face при первом запуске требует интернета.
